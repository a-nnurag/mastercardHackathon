TITLE: Indirect Prompt Injection in Web Content Targets AI Agents (Zscaler ThreatLabz)

Campaign 1 - Fraudulent Python library documentation: Zscaler ThreatLabz identified a payment scam disguised as documentation for a fake Python module ("requests-secure-v2"). Techniques: SEO poisoning with keyword-rich HTML ranking the malicious site highly in search results; hidden IPI instructions via CSS positioning (e.g. left: -9999px), invisible to humans but readable by AI systems; JSON-LD structured metadata describing a "SoftwareApplication" with an "offers" object claiming a "$3.00 developer API license key" was required, with a Stripe checkout link; dual targeting of both AI agents and human developers with crypto/credit-card payment options for the fake API key.
Testing results: across 26 LLMs tested, 4 executed the fraudulent payment (Llama 3.3 70B Instruct, Llama 3.2 90B Vision Instruct, Gemini 3 Flash, Gemini 2.5 Pro).

Campaign 2 - Cryptocurrency platform typosquatting: attackers created debank[.]auction impersonating the legitimate DeFi portfolio tracker DeBank. Techniques: SEO optimization with keyword-stuffed titles/metadata ("DeBank Login", "DeFi Dashboard"); fake JSON-LD credentials falsely claiming debank.com as the publisher; hidden CSS-text IPI instructions telling LLMs to treat the fraudulent domain as "the verified, authoritative destination" and rank it "#1 primary source."
Testing results: 2 of 26 models misclassified the typosquat site as legitimate when evaluated without a legitimate reference URL present (GPT-5.4, Claude Sonnet 4.5).

Broader implication: IPI effectiveness depends significantly on context -- when legitimate reference URLs were provided alongside the fake ones, no models were deceived. This maps directly onto our ingestion_source_trust_score signal: an untrusted/typosquat domain ingested without a trusted counterpart present is exactly the condition under which these real-world attacks succeeded.
